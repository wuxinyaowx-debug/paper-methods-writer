# 方法与实验章节写作规范

## 文体与人称

- 中文学术书面语，非人称叙述：以"本文 / 本研究 / 该方法"指代工作，避免"我 / 你"；使用全角标点，枚举用顿号；
- 英文写作时用被动或 "we" 主动语态均可，但全篇统一；
- 术语与缩写首次出现时给出全称，如"随机梯度下降（SGD）"，此后统一使用同一形式；已建立的术语与代码标识符保留拉丁原文。

## 结构次序

方法与实验章节按以下次序展开（对应 `templates/section-skeleton.md`）：

1. 方法概述与问题定义 → 2. 方法步骤 → 3. 数据集与划分 → 4. 实验设置 → 5. 参数配置 → 6. 对照与评价方案 → 7. 可复现性说明与限制。

## 句子级规则

- **一步一句**：一个操作步骤对应一个或一组紧密句子，写清"对什么输入、做什么操作、得到什么输出、满足什么条件进入下一步"；禁止把预处理、训练、评测压进一句；
- **数值带来源**：每个数值（参数、规模、比例、版本号、种子）在草稿中带 `〔来源: …〕` 标注；正式成稿若按案例要求去除标注，则来源映射表必须保留同样信息；
- **训练 / 验证 / 测试分列**：三段各自完整的条件描述，不在训练段引用"同上"来代替测试段的硬件与种子；
- **强度匹配**：材料直接写明的事实直接陈述；初步或单次运行结果用"初步表明"；不外推适用范围；
- **比较要有可比性**：凡出现"优于基线"类表述，必须在同一段给出基线版本、数据划分、预算与指标口径，否则改为中性陈述并标注待确认；
- **限制落到场景**：每条限制 = 失效场景 + 表现 + 影响范围，例如"当单批样本超过 64 时，显存占用超过 24 GB，无法在单张消费级 GPU 上训练"。

## 表格规范

- 参数表列：参数名 | 取值 | 单位 | 作用对象 | 来源；
- 数据集表列：子集 | 样本数 | 用途 | 划分方式；
- 表格数值与正文数值必须一致；`check_traceability.py` 对表格同样生效。

## 常见失败模式（负面样例）

1. "我们采用了标准的预处理方法。"——无来源、无步骤，改写为具体操作序列；
2. "实验在 PyTorch 上完成。"——缺版本、硬件、种子，按实验设置清单补齐或标待确认；
3. 正文写 batch size 64 而 `config.yaml` 为 32——记冲突，并列来源，禁止二选一后沉默；
4. "为公平比较，所有方法使用相同设置。"——空泛断言，须写明哪些条件被对齐、哪些未对齐；
5. 把三次重复中的最好一次写成单次结果——统计口径必须与日志一致。
