# 方法与实验（章节骨架模板）

> 用法：逐节填充。每个数值后保留 `〔来源: 文件, 定位〕`；材料缺失处写 `〔待确认: …〕` 并登记 `gap_report.md`。
> 若案例任务另有体裁、语言或格式要求（见 case.json / task.md），以案例要求为准，本骨架只规定要素覆盖。

## X.1 方法概述

用 1–2 段说明任务定义（输入、输出、目标）与方法总体思路。所有问题规模、符号定义与材料一致。

## X.2 方法步骤

按执行顺序分步描述，每步写清输入、操作、输出与判断条件：

1. **步骤 1（名称）**：输入 …；执行 …；输出 …；当 … 时进入下一步。〔来源: 代码文件, 行号〕
2. **步骤 2（名称）**：……
3. ……

## X.4 实验设置

分三小节描述，条件不得互相借用：

**训练**：硬件（型号 × 数量）…；软件（OS、CUDA、框架及版本）…；优化器 …；学习率 …，调度 …；batch size …；训练轮数 / 步数 …；随机种子 …；重复次数与统计方式 …。每项带来源或待确认标注。

**验证**：验证频率、早停准则、模型选择标准 …。

**测试**：测试环境与硬件、权重来源（哪个检查点、按什么标准选出）、评测脚本版本 …。

## X.6 对照与评价方案

- 基线：名称、版本 / 出处、复现或引用原数值。〔来源〕
- 可比性：数据划分、预算（步数 / 搜索量 / 硬件）是否对齐；未对齐处显式说明。
- 评价指标：定义、实现（官方脚本 / 自实现）、统计方式（均值 ± 标准差，n = …）。

## X.7 可复现性说明与限制

- 复现清单：代码版本（commit / tag）、环境、数据获取方式、运行命令。〔来源〕
- 运行成本：训练时长、显存占用。〔来源〕
- 限制：每条写清失效场景、表现与影响范围；无材料支撑的限制写 `〔待确认〕`。
